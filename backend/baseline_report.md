# DataPulse baseline report

Generated by `backend/baselines.py` (run: `.venv/bin/python -m backend.baselines`
from the project root). Same seeded scenario as `backend/evals.py` (seed=7,
80-tick warmup, each injectable anomaly for 30 ticks, 40 settle ticks between).
Reproducible: re-running gives identical numbers.

> **Status (Oct 2026):** the IsolationForest layer was **removed** from the
> shipped detector (`backend/detector.py`) based on these results. The IF
> variants below are **experimental ablation only**, rerunnable via
> `LegacyIFDetector` in `baselines.py`. The shipped detector is
> **robust z-score + schema-drift check** — F1 0.98 on the seeded suite.

Honest reading: on this suite the robust z-score layer does all the work.
The IsolationForest layer (contamination=0.03, threshold −0.15) never fires
on the injected anomalies — verified: IF decision scores on injected ticks
range −0.024…0.127, never below −0.15. The shipped suite injects
large single-metric shifts, which is exactly what z-score is built for.
Experiment 3 below tests multivariate correlated anomalies — the case
where IF should help — and finds it doesn't there either.

## Experiment 2 — narration baseline

| setup | citation rate (6 incidents) | off-topic abstains |
|---|---|---|
| rag-grounded (shipped) | 100% (6/6 cite a runbook) | yes — "I couldn't find anything relevant in the runbooks…" |
| plain-llm, no retrieval | 0% (0/6) | no — fabricates a generic answer |

Comparison is on verifiable properties (citation presence, abstention),
not prose quality, which would need human rating. The plain baseline shows
the failure mode RAG+abstention removes: confident, ungrounded answers.

## Experiment 3 — multivariate anomalies (correlated, sub-threshold shifts)

Two new injectable kinds (kept out of the shipped INJECTABLE suite so demo
numbers don't change). Each metric shifts ~2.3σ — under the z=3.5
threshold on its own; only the joint pattern is anomalous.

| anomaly | zscore-only | if-only | combined | if-scaled |
|---|---|---|---|---|
| slow_burn (latency+nulls drift) | 0.07 | 0.00 | 0.07 | 0.00 |
| silent_corruption (rows dip + dups rise) | 0.27 | 0.00 | 0.27 | 0.00 |

recall = fraction of injected ticks flagged.

Diagnosis — why even the scaled IF fails: with 60 warmup points in 5
dimensions, the IsolationForest has no discriminative power at all.
Training score_samples span only [−0.576, −0.383] (range 0.19), and a
46σ volume spike scores −0.566 — inside the normal range. The shipped
threshold (−0.15) is never reached by anything, normal or anomalous.
The IF layer, as configured, cannot detect what it was built for.

Honest conclusion: on every tested scenario the robust z-score layer
carries detection and the IF layer adds zero measurable value —
unscaled or scaled. **Decision (Oct 2026): the IF layer was removed**
from `backend/detector.py`; the shipped detector is robust z-score +
schema-drift check. Subtle correlated drift (~2σ) remains an open
challenge, stated as future work.
